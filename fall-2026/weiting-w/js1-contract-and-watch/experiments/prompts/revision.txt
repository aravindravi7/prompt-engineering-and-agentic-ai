You are judging ONE job posting against ONE resume for a job-search agent.
The resume belongs to a fictional persona, not a real person.

THE RULE (R-v2). There are four gates. A posting is "relevant" only if all
four pass.

G1_title_block - fails if the posting title contains, as a whole word, any
  token in title_block. Whole word means bounded by a non-letter or by the
  start or end of the string, so "sr" does not match "sre" and "lead" does
  not match "leadership".
G2_discipline - fails if the posting title contains none of the phrases in
  target_title_phrases as a substring.
G3_job_family - let F be the value of the posting's metadata entry whose
  name is "Job Family". Fails if F is missing, empty, or contains none of the
  phrases in target_job_families as a substring.
G4_location - fails if the posting's location name contains none of the
  phrases in locations_ok as a substring, and it is not the case that
  remote_ok is true and the location name contains "remote".

Evaluate the gates strictly in the order G1_title_block, G2_discipline,
G3_job_family, G4_location, stop at the first gate that fails, and report that
first failing gate; do not report a later gate when an earlier one has
already failed.

All comparisons are case-insensitive. You may use only the posting fields
printed below; there is no job description available to you.

RESUME FIELDS (already lower-case):
{resume_block}

POSTING:
{posting_block}

OUTPUT FORMAT. Reply with a single JSON object and nothing else - no prose
before or after it, no code fence:

{{"posting_id": <int>, "verdict": "relevant" | "not_relevant", "gate_failed": <gate id or null>, "justification": [{{"resume_field": "<path>", "posting_field": "<path>", "evidence": "<string>"}}], "confidence": "high" | "medium" | "low"}}

Field requirements:
- posting_id must be exactly the id printed above.
- gate_failed must be null when verdict is "relevant", and otherwise exactly

  "title_block[0]", "target_title_phrases[2]", "target_job_families[0]",
  "locations_ok[3]", "remote_ok".
- posting_field must be a path into the posting above, for example "title",
  "location.name", "metadata[4].value", "metadata[4].name".
- evidence must be a string that literally occurs, case-insensitively, inside
  the posting field you named.
- confidence is your own, about this verdict.
